How We Talk to Each Other

The Default Is Writing

This organization runs on written words. Discussions happen in writing. Decisions are recorded in writing. Context is shared in writing.

The default is asynchronous, public, and permanent. Before you schedule a meeting, ask: Could this be a written update? Before you ask a question in a direct message, ask: Would someone else benefit from seeing the answer?

A written organization is a generous organization. Writing things down means the person who joins six months from now can understand a decision made today. It means the person in a different timezone can participate fully. It means context is not locked inside someone’s head.

Where Things Live

We use a few shared spaces, each with a clear purpose:

The Signal is where conversation happens. It is organized into channels by topic — projects, domains, interests, and social spaces. Default to public channels. Direct messages are for the things that genuinely should not be public, not for the things that are merely easier.

The Record is where durable information lives. Project overviews, decision records, process documentation, team handbooks — anything someone might need to find later. If you learn something that took effort to figure out, it belongs in the Record.

The Forge is where code and code review happen. Every change is proposed, discussed, tested, and merged through the Forge. It is the source of truth for what has been built and why.

The Map tracks what is being worked on and what is coming next. It answers: What is in progress? What is blocked? What is planned? The Map is a shared view — anyone in the organization can see what anyone else is working on.

Writing Well

Writing is the organization’s primary skill. A few habits make it work:

Write for someone who will read it months from now. Give context. Explain why. Link to related decisions and discussions. A document that only makes sense to three people today will make sense to nobody tomorrow.

Default to public. Unless the content is personal, sensitive, or legally restricted, it belongs in a shared space. Err on the side of visibility.

Make decisions findable. The title of a decision record should describe the decision, not the date it was made. “ADR: Use DynamoDB for event storage” is findable. “Meeting notes from March 12th” is not.

Use threads. Long discussions in a single channel are hard to follow later. Start a thread, write your thinking, and let the conversation branch from there.

Write the summary first. If a document is long, start with a three-sentence summary. The reader who needs only the conclusion should not have to dig for it.

When Writing Is Not Enough

Some things are better said than written. A conversation can resolve a misunderstanding that ten messages would amplify. A call can communicate care in a way text cannot.

The principle is not never talk. It is write down what you talked about. After a meaningful conversation, post a short summary in the relevant public channel. “Spoke with Alex about the deployment schedule. We agreed to defer the Friday release to Monday. Rationale in the Record.”

This habit — writing after talking — is how the organization stays written-first without sacrificing human connection.

Asking Questions

Pretending to know is more expensive than asking. Nobody expects you to understand everything on day one. Nobody expects you to understand everything on day one hundred.

Ask in public channels when the answer might help others. Ask in direct messages when the question is personal. Ask early, before you have spent three hours going down the wrong path.

The organization values curiosity over certainty. A thoughtful question is respected more than a confident wrong answer.

If you are stuck, say so. “I am stuck on X and I have tried Y and Z” is one of the most productive messages you can send. It gives people enough context to help and it signals that you have already put in the work.
